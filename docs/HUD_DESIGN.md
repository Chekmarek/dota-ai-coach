# Подсказки поверх игры: как устроен дизайн и как его поменять

Этап 3 (0.12.0), редизайн 2026-10-18. Всё визуальное отделено от логики: редизайн — это правка токенов темы и проверка на странице
«Подсказки в игре» в приложении (или снимками `node scripts/hud-snapshot.mjs`).

## Где что лежит

| Что | Файл | Что менять |
|---|---|---|
| Токены темы (цвета, шрифты, размеры, тени, длительности, кривые) | `src/hud/theme/tokens.ts` (описание), `src/hud/theme/themes/*.ts` (значения) | Новая тема = новый файл + строка в `src/hud/theme/index.ts` + id в `HUD_THEME_IDS` (`src/shared/types/hud.ts`) |
| Анимации (именованные пресеты) | `src/hud/theme/motion.ts` | `enter`, `exit`, `reflow`, `pulse`, `update` — только `transform`/`opacity` |
| Компоненты | `src/hud/components/cards.ts` (HintCard, AlertBanner, DecisionCard, ReviewPanel), `icons.ts` (Emblem, значки важности) | Разметка; цветов и размеров в них нет — только классы `hud-*` |
| Стили | `src/hud/hud.css` | Только `var(--hud-*)` из темы |
| Раскладка (зоны и запретные области HUD Dota) | `src/data/hud-overlay-layout.json`, расчёт — `src/core/hud/layout.ts` | Отдельно от темы. Пользовательские сдвиги — «Режим расстановки» (`settings.hud.zones`) |
| Примеры подсказок | `src/shared/hud-samples.ts` | Сцены «Игра идёт», «Герой мёртв», «Конец матча» |

## Единицы и любые экраны

Размеры в токенах — в тысячных `u`, где `u = min(высота, ширина × 9/16)`: так масштабируется HUD Dota (по высоте,
а на экранах уже 16:9 — по ширине). Зоны привязаны к краям/середине экрана, поэтому одна раскладка работает на
16:9, 16:10, 21:9, 32:9, 4:3, ноутбуке 1366×768 и телевизоре 4K. Тест `tests/unit/hud-layout.test.ts` проверяет,
что зоны не заходят на HUD игры и не выходят за край на всех этих экранах. «Размер» в настройках увеличивает карточки
внутри зоны, а не саму зону: что не влезло — не показывается.

## Стиль (0.13.3+, решение владельца 2026-10-18)

Прежний стиль «камень, руны, магия» (2026-10-16) заменён по просьбе владельца: он закрывал пол-экрана. Теперь —
компактные плашки «тактической аналитики»: тёмная подложка (90 % непрозрачности — читается на любой сцене), тонкая
кромка, один акцент темы («Бирюза» по умолчанию, «Аметист»; id тем `runes`/`obsidian` сохранены ради старых настроек).
Все значения и правила — в `DESIGN.md` в корне репозитория.

- Иерархия: действие (заголовок) → причина (≤ 2 строк, без повтора заголовка — `src/core/hud/text.ts`) → число % →
  факторы только в «Подробно» (не больше трёх).
- Важность не только цветом: срочно — треугольник «!», слово «Срочно», красная кромка и подложка; совет — стрелка в
  круге; информация — без значка.
- Состояния: новая (въезд + вспышка), актуальная (повтор правила продлевает срок), устаревает (последние 30 % срока —
  плашка блекнет, CSS по `--ttl`), устарела (очередь снимает ситуативную подсказку через 2,5 с после того, как правило
  перестало её подтверждать — `HintQueue.expireStale`), недоступна (нет картинки и данных игры — окно не показывает
  подсказки, значок «Коуч» пишет причину).
- «Что показывать» (`settings.hud.hiddenZones`): любую зону можно скрыть; «Сколько текста» = `settings.hints.detail`.

## Производительность

Окно спрятано, пока подсказок нет (0 % CPU). Своих таймеров у страницы нет; анимации — Web Animations API и CSS на
transform/opacity, пульс критичных — 3 раза и стоп.

Замер `node scripts/perf-hud.mjs [папка сборки]` (2026-10-18, Ryzen 5 5600X + RTX 3070 Ti, 5 демо-плашек на экране,
окно 8 с, по 2–3 прогона):
