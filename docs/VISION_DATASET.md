# Набор кадров для проверки зрения

Зачем: чтобы честно мерить, насколько коуч видит союзников и врагов (верхняя панель, мини-карта, полоски здоровья),
нужны настоящие кадры игры **с правильными ответами**. Правильные ответы даёт сама Dota: в режиме наблюдателя
(просмотр записи матча или чужой игры в клиенте) Valve GSI присылает положение, здоровье, уровень, смерть и время
возрождения **всех 10 героев**. Коуч сохраняет кадр живого захвата вместе с последним таким телом GSI — получается
размеченный кадр без ручной работы.

## Как записать

1. GSI должен быть подключён: «Живая игра» → «Подключить», в Steam у Dota 2 параметр запуска `-gamestateintegration`.
2. Запустить коуча в режиме разработчика — с переменной окружения `DOTACOACH_DEV=1`. Например, в PowerShell:
   ```powershell
   $env:DOTACOACH_DEV = '1'; & "$env:LOCALAPPDATA\Programs\DotaCoach\DotaCoach.exe"
   ```
   (из исходников: `$env:DOTACOACH_DEV = '1'; npm run dev`). Без этой переменной запись не включится, даже если
   настройка сохранена.
3. «Настройки» → «Для разработчика: набор кадров» → включить «Сохранять кадры». «Каждый N-й кадр»: при захвате
   10 к/с N = 10 даёт кадр в секунду — достаточно; чаще не нужно (соседние кадры почти одинаковые).
4. В Dota открыть запись матча (Watch → Replays / вкладка матча → «Смотреть»), живой захват коуча включён.
   Смотреть на скорости ×1, интерфейс Dota по умолчанию (16:9, мини-карта на обычном месте и обычного размера,
   иконки героев на мини-карте).
5. Кадры появляются в `<папка данных>\vision-dataset\<дата>\`: `ЧЧММСС-ммм-номер.png` + `.json`
   (папка данных — «Настройки» → «О программе»).

**Сначала проверить одну минуту записи:** открыть любой `.json` — поле `spectator` должно содержать 10 героев с
`xpos`/`ypos`. Если там `null` — Dota в этом режиме не присылает данные наблюдателя (формат GSI наблюдателя пока
проверен только на синтетическом теле `tests/fixtures/gsi/spectator.json`); тогда напишите об этом — нужно будет
разобраться с конфигурацией GSI, прежде чем записывать дальше.

## Сколько нужно

- **Не меньше 2 000 размеченных кадров из 5 и больше записей.**
- Разные герои в обеих командах (иконки на мини-карте и портреты сверху), и день, и ночь.
- И лайнинг (много героев на линиях, крипы, полоски здоровья рядом друг с другом), и драки (5 на 5, смерти,
  таймеры возрождения на верхней панели), и спокойные минуты (герои в тумане войны, «пропавшие»).
- Желательно хотя бы одна запись, где кто-то умирает несколько раз (таймер возрождения), и одна — после 40-й минуты.

Место: кадр 1920×1080 в PNG — около 3–4 МБ, 2 000 кадров — 6–8 ГБ. Не больше 20 000 кадров в папке одного дня (≈ 60 ГБ).

## Личные данные

- В `.json` ники, steamid и accountid **вырезаются** (как в записях сессий GSI), остаются ключи героев.
- **На самих кадрах ники видны** (верхняя панель, табло, чат). Поэтому набор хранится только в папке данных
  и **никогда не коммитится** в репозиторий. Для тестов в репозитории — только вырезанные области без ников.

## Как проверить зрение

```
node scripts/vision-eval.mjs "<папка данных>\vision-dataset" [--limit 500] [--per-frame]
```

Для размеченных кадров печатается точность по каждому полю (прочитано / верно), для неразмеченных — сколько
прочитано, сколько раз «кто это» менялся между соседними кадрами, падения и время на кадр.

Записи «Разбора записи» (видео без разметки) проверяются так же — сначала кадры из видео:

```
node scripts/video-frames.mjs "<видео.mp4>" .tmp\video-frames\<имя> --every 30
node scripts/vision-eval.mjs .tmp\video-frames
```

`.tmp` в git не попадает.

### Полоски здоровья героев (этап 3)

Полноту и ложные срабатывания по GSI не посчитать: GSI наблюдателя знает всех героев, но не знает, кого видно
на экране (туман, невидимость, камера в стороне). Поэтому они считаются по **ручной разметке**:
`tests/fixtures/healthbars/labels-2026-10-14.json` — 96 кадров матчей, не участвовавших в настройке (по 24 на матч,
равномерно по времени); каждая полоска героя проверена глазом, полоски крипов и призванных существ не размечены.
Ошибка HP — по GSI на всех кадрах: полоска сравнивается с героем, только если её цвет и прочитанный уровень
совпадают ровно с одним живым героем.

```
node scripts/vision-eval.mjs "<папка данных>\vision-dataset" --labeled-only
```

Цвет у наблюдателя: зелёные полоски — Силы Света, красные — Силы Тьмы; у игрока — свои и противник.

## Отладочная запись своей игры («Записывать кадры», с 0.17.x)

Работает без режима разработчика: «Живая игра» → карточка «Запись кадров для отладки зрения» → «Записывать кадры».
По умолчанию выключено; настройка `live.recordFrames` (старые `settings.json` без неё читаются, значение — выключено).

- Раз в 2 с: кадр **в полном разрешении окна** (захват на время записи переподключается с пределом 3840 px; зрение
  по-прежнему получает кадр, уменьшенный до «максимальной ширины кадра»), PNG без потерь.
- Вырезки: `-minimap.png` — та область, которую сейчас читает зрение (по самокалибровке или по раскладке), и
  `-topbar.png` — середина верха (840×64 при высоте 1080).
- `.json`: размер потока и кадра, формат `VideoFrame` (`format`, `colorSpace`, coded/display размер), настройки трека
  (`getSettings`), частота и задержка захвата, скорость зрения; окно Доты (клиентская область, физические пиксели),
  монитор (размер, масштаб Windows), строки `setting.*` из `video.txt`; сводка того, что зрение увидело на последнем
  кадре (верхняя панель, значки мини-карты, полоски здоровья) и тело GSI без ников и steamid.
- Папка: `<папка данных>\frame-records\<ГГГГ-ММ-ДД_ЧЧММСС>\`; не больше 3000 кадров за запись (≈ 1 ч 40 мин).
  Около 3–5 МБ на кадр. На кадрах видны ники — в репозиторий не коммитить.
